# The Bug Bazaar

A small store for developer gear (rubber ducks, mechanical keyboards, coffee and stickers), built with **React 19 + TypeScript (strict)**. It runs entirely in the browser against a mock API of 5,000 products, so there is no backend to set up.

## Quick start (about 2 minutes)

**Prerequisites:** [Node.js](https://nodejs.org) **22.12 or newer** (`node -v` to check; `nvm use` picks the right version from `.nvmrc`) and Git.

```bash
git clone https://github.com/tjaved-folio3/transformation-assignments.git
cd transformation-assignments
git checkout feature/bug-bazaar   # until the PR is merged into main
npm install
npm run dev
```

Open the URL Vite prints (usually http://localhost:5173). That's it: no `.env` file is needed.

**Demo login:** `dev@bugbazaar.test` / `password123`

## Scripts

| Command                           | What it does                                                      |
| --------------------------------- | ----------------------------------------------------------------- |
| `npm run dev`                     | Start the dev server with hot reload                              |
| `npm run build`                   | Type-check, then build for production into `dist/`                |
| `npm run preview`                 | Serve the production build locally                                |
| `npm run typecheck`               | Run the TypeScript compiler (strict mode, no output)              |
| `npm run lint`                    | ESLint (bans `any`, `@ts-ignore`, and `fetch` outside `src/api/`) |
| `npm run format` / `format:check` | Format with Prettier / check formatting                           |
| `npm test` / `test:watch`         | Run the Vitest test suite once / in watch mode                    |
| `npm run check`                   | Everything CI runs: lint + typecheck + format check + tests       |

## Environment variables

All optional. To change one, copy `.env.example` to `.env.local` (git-ignored).

| Variable            | Default | Purpose                                                         |
| ------------------- | ------- | --------------------------------------------------------------- |
| `VITE_API_BASE_URL` | `/api`  | Base URL for every API request                                  |
| `VITE_ENABLE_MOCKS` | `true`  | `false` turns off the mock API so requests go to a real backend |

## The mock API and triggering errors

[MSW](https://mswjs.io) intercepts `fetch` calls in the browser and answers from `src/mocks/`. A **Mock API controls** panel (bottom-right) lets you force a 500, 409 or 401 and slow the network down. See [`docs/api-contract.md`](docs/api-contract.md) for every endpoint and how to trigger each error.

## Folder structure

```
docs/                 Written tasks: API contract, decisions, architecture, …
public/
  images/             Category images used by the seed data
  mockServiceWorker.js  Generated by MSW (do not edit)
src/
  api/                The data layer: the ONLY code that makes network requests
  mocks/              Mock backend: seed data, fake DB, request handlers, Dev panel
  types/              Shared TypeScript types (API contract, request state)
  store/              Redux Toolkit store, slices and selectors (cart, session)
  features/           Feature folders (products, cart, auth, orders): pages + their components
  components/         Shared UI building blocks (layout, loading/empty/error states)
  hooks/              Reusable custom hooks (debounce, scroll position, API queries)
  utils/              Small pure helpers (price formatting, …)
  test/               Test setup (MSW server for Node)
```

## Tech stack

React 19 · TypeScript 6 (strict) · Vite 8 · React Router · Redux Toolkit · MSW · Vitest + Testing Library · ESLint + Prettier. Why each was chosen is in [`docs/decisions.md`](docs/decisions.md).

## Troubleshooting

- **`npm install` fails or `npm test` errors on startup:** check `node -v` is 22.12 or newer.
- **Products never load / "Failed to register a ServiceWorker":** open the app on `localhost` (Service Workers need `localhost` or HTTPS), and do a hard reload (Ctrl+Shift+R).
- **Everything errors:** open the Mock API controls panel and untick any forced errors, or click **Reset mock data**.
